# SFE Ядран — Дашборд медицинского представителя

Статичный веб-инструмент (HTML/CSS/JS, без бэкенда) на основе переписи аптек
«Ядран» (1 кв. 2026, 86 227 точек, 90 регионов).

## Структура
```
index.html        — само приложение
data/_index.json   — сводка по регионам (лёгкий файл, для вкладки «Сравнение регионов»)
data/<REGION>.json — данные по каждому региону, подгружаются по выбору территории
```

## Как запустить локально
Открыть `index.html` двойным кликом **не сработает** — браузер блокирует загрузку
`data/*.json` через `file://` (CORS). Нужен локальный сервер:

```bash
cd sfe-yadran-dashboard
python3 -m http.server 8080
# затем открыть http://localhost:8080
```

## Как задеплоить в работу
Это набор статичных файлов — подходит любой статический хостинг:

- **Netlify / Vercel**: перетащить папку в интерфейс деплоя (drag-and-drop) — ничего
  настраивать не нужно.
- **GitHub Pages**: закоммитить папку в репозиторий, включить Pages в настройках.
- **Внутренний корпоративный сервер**: скопировать папку целиком в директорию,
  которую раздаёт nginx/IIS/Apache.

## Как обновить данные при новой выгрузке

Когда получишь свежий файл переписи или свежую выгрузку SFE — не нужно писать
код заново, всё пересобирается одной командой через `build_data.py` (лежит в
корне проекта).

```bash
pip install pandas openpyxl        # один раз
python3 build_data.py --census НОВАЯ_ПЕРЕПИСЬ.xlsx --sfe НОВАЯ_МОДЕЛЬ_SFE.xlsx --outdir data
```

Можно обновлять источники по отдельности:
```bash
python3 build_data.py --census НОВАЯ_ПЕРЕПИСЬ.xlsx     # только территории/точки
python3 build_data.py --sfe НОВАЯ_МОДЕЛЬ_SFE.xlsx      # только вкладка «Мои показатели (МП)»
```

Скрипт перезапишет файлы в `data/` и выведет сводку (сколько точек, сколько МП,
сколько сопоставилось по ID). Дальше — обычный git-цикл:

```bash
git add data/
git commit -m "Обновление данных: <дата>"
git push
```

Railway подхватит пуш и передеплоит сайт за 1–2 минуты автоматически (Auto Deploy
включён по умолчанию) — вручную в интерфейсе Railway ничего нажимать не нужно.

**Если структура исходного файла поменяется** (переименуют колонку, поменяют формат
файла SFE со сводной таблицы на плоский экспорт и т.п.) — скрипт остановится с понятным
сообщением, какой колонки не хватает, вместо того чтобы тихо собрать неправильные
данные. В этом случае пришли мне обновлённый файл — поправлю скрипт под новую структуру.

## Хранение данных пользователя
Отметки «Целевая точка» и порядок маршрута сохраняются в `localStorage` браузера —
то есть привязаны к конкретному браузеру/устройству, на котором работает
представитель, и не сихронизируются между устройствами. Если нужна синхронизация
между устройствами или между несколькими представителями (общая база), это
следующий шаг — потребуется небольшой бэкенд или база данных.

## Известные ограничения текущей версии
- **Нет геокоординат** в исходной переписи → вкладка «Карта» показывает разбивку
  по городам, а не точки на настоящей карте. Для полноценной карты нужно
  геокодировать адреса (отдельная задача).
- **Маршрутизация ручная** — по той же причине (нет координат) расстояния между
  точками не считаются автоматически, только ручная сортировка.
- **XYZ-анализ не считается** — требует истории продаж за несколько периодов,
  а перепись — снимок на один квартал. Во втором загруженном файле
  («Модель сегментации SFE Q3'25») такая история по кварталам есть — при
  сопоставлении по адресам можно будет досчитать XYZ отдельным шагом.
- Скоринг точки — эвристическая модель (категория ТО 50% + средний чек 25% +
  доля ЛП 15% + принадлежность к сети 10%), не фактические продажи. Её веса
  можно и нужно откалибровать под реальные данные компании.
